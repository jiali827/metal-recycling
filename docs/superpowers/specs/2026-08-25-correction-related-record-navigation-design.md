# 纠错关联记录导航设计

## 目标

在纠错删除弹窗中，让受影响的横向业务记录可直接进入其所属列表，并自动填充对应编号筛选。用户可在目标列表继续使用既有的详情、作废、撤销或冲销能力。

## 范围

弹窗将只把下列纠错动作渲染为可跳转的关联记录：

- `void_ticket`：过磅台账，按磅单号筛选。
- `revoke_contract`：采购或销售合同，按合同号筛选，并切换到对应合同页签。
- `revoke_settlement`：结算单，按结算单号筛选。
- `reverse_payment`：收付款，按收付款单号筛选。

`void_arap` 与 `restore_arap` 继续参与影响汇总，但不作为关联记录行展示，也不提供跳转。它们是结算单派生往来余额，不是本需求中可横向操作的业务记录。

## 交互与数据流

每个可跳转记录渲染为覆盖整行宽度的原生按钮，右侧显示 `>`。按钮使用 `router.push` 跳转到列表页，并关闭纠错删除弹窗。

跳转 URL 使用稳定、可分享的查询参数：

| 业务对象 | URL | 目标筛选 |
| --- | --- | --- |
| 过磅台账 | `/weigh-tickets?bxNo={磅单号}` | 磅单号 |
| 采购合同 | `/contracts?tab=purchase&contractNo={合同号}` | 采购页签和合同号 |
| 销售合同 | `/contracts?tab=sale&contractNo={合同号}` | 销售页签和合同号 |
| 结算单 | `/settlement-docs?docNo={结算单号}` | 结算单号 |
| 收付款 | `/payments?paymentNo={收付款单号}` | 收付款单号 |

各列表页从 `useSearchParams` 初始化相应本地筛选状态。筛选逻辑使用精确编号字段，不依赖当前通用关键字，确保同一条记录能稳定定位。用户调整筛选后不强制同步 URL，保持现有列表的本地筛选交互。

## 测试

把纠错动作转换为深链的规则提取为纯函数，测试四类可跳转动作、合同页签区别和应收/应付动作被排除。页面层通过复用该规则，避免 UI 与 URL 映射出现分叉。
