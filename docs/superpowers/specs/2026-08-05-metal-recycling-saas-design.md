# 金属回收管理系统（多租户 SaaS）设计规格

**日期：** 2026-08-05  
**状态：** 已确认（头脑风暴）  
**首个验证租户：** 寶新金屬回收有限公司（BAO XIN METAL RECYCLE LIMITED）  
**业务参考：** 客户提供的 Excel / 纸质磅单 / 现有过磅软件界面（含源佳账本逻辑，与寶新一致）

---

## 1. 背景与目标

### 1.1 问题

金属回收公司（以寶新为例）目前用：

1. 地磅仪表 + 旧 Windows 过磅软件（串口读磅、打印纸质「秤重報告過磅單」）
2. Excel《鐵料當日磅單》誊抄作业
3. Excel《鐵料收支記錄》做买卖、应收应付、现金结余

痛点：重复录入、单价与合同易脱节、账容易错、难总览营收与资金。

### 1.2 目标

建设云端 Web 多租户系统，服务多家同类金属回收公司。以**合同为中心**约束单价与履约，用过磅台账替代 Excel，用往来收付管理营收与资金；逐步弱化纸质单+Excel 双轨。

### 1.3 成功标准（一期）

- 过磅必须关联有效合同，单价不可在过磅页随意改
- 同一租户内磅单号与纸质 BX 单号可对齐核对
- 采购/销售过磅自动形成应付/应收，支持收付款核销
- 首页同时展示经营概览与资金概览
- 多租户数据隔离；租户可注册、添加员工、配置角色权限
- 以寶新为第一个租户验证全流程

## 2. 用户与权限

### 2.1 平台级

| 角色 | 职责 |
|------|------|
| 平台超管（运营方） | 租户停用/启用等运营动作；默认不查看各租户业务明细（开户为用户自助注册，见 §4） |

### 2.2 租户内预置角色模板（可配置权限点）

| 角色 | 职责 |
|------|------|
| 系统管理员 | 基础参数、员工账号、角色权限 |
| 合同管理员 | 采购/销售合同 |
| 过磅人员 | 过磅台账（挂合同、录重量、对纸质单号） |
| 财务 | 应收应付、收付款、营收相关 |
| 老板 | 本租户全局总览、各业务开展情况 |

同一套系统、按角色授权；所有业务数据限定在当前租户。

## 3. 范围

### 3.1 一期（分批）

**规划边界（重要）：** 下一份实现计划（writing-plans）**只覆盖「首批上线」**。一期后半段另开计划，不与首批混在同一份实施计划里。

**首批上线（第一份实现计划范围）：**

- 多租户：自助注册创建公司租户、员工、角色权限、数据隔离
- 基础参数：客户、货类、收付方式等
- 合同管理（采购/销售）
- 过磅台账：手录总重/皮重/扣减；必须挂合同；单价只读带出；电子磅单；BX 单号与纸质单对齐
- 往来：应收/应付由磅单生成；收付款核销；客户往来余额
- 首页：经营概览 + 资金概览
- 双轨打印：旧软件继续打印纸质单；Web 不做取代套打

**一期后半段（后续单独计划，仍属一期产品目标）：**

- 更完整报表（货类日汇总、对账单、月报导出等）
- 杂项开支（运费、PETTY CASH、薪金等）并入现金流水

### 3.2 二期及以后

- 分拣/压缩入库工序
- 地磅串口自动读数（本地桥接服务）
- Web 套打取代旧过磅软件打印
- 精细库存成本与盈亏估值
- 源佳等其它公司作为独立租户接入（逻辑与寶新相同）

### 3.3 明确不做（一期）

- 完整会计总账/凭证体系
- 跨租户的老板总览（老板只看本租户）
- 强制对接旧过磅软件数据库（一期手录）

## 4. 多租户模型

```text
平台
 └── 租户 = 一家回收公司
       ├── 公司资料 / 基础参数（租户自管）
       ├── 员工与角色权限
       └── 业务数据（合同、磅单、往来…）与其他租户隔离
```

- **开户默认：自助注册即创建公司租户**（注册人成为该租户系统管理员）。平台超管可事后停用违规/欠费租户，不作为日常开通闸门。
- 租户管理员添加/停用员工
- 预置五类角色模板，允许调整权限点
- 所有业务表带 `tenant_id`；API 强制租户校验

寶新是第一个落地租户；产品按行业模板建设，不写死单公司。

## 5. 核心业务设计

### 5.1 主数据流（合同中心）

```text
基础参数（客户、货类…）
    → 合同（货类、单价、约重、对方、日期等）
    → 旧软件看磅/打纸质单
    → Web 录同号磅单（挂合同，单价只读）
    → 生成应收或应付
    → 财务收付款核销
    → 首页经营 + 资金指标
```

### 5.2 合同

| 类型 | 对方 | 过磅后 |
|------|------|--------|
| 采购合同 | 供应商 | 应付 |
| 销售合同 | 买家（含出口） | 应收 |

- 状态：`草稿 → 生效 → 履约中 → 已完成 / 已关闭`
- 仅「生效 / 履约中」可被过磅选用
- **状态触发默认：** 合同管理员将草稿「生效」；**首笔有效过磅**自动变为「履约中」；累计净重达到约重（或管理员手动关闭）→「已完成 / 已关闭」
- 一份合同支持多次过磅（多车、多日）
- 累计净重对照合同约重；接近/超过时警告（是否硬拦截可配置，默认警告）
- 无有效合同不得落正式磅单；散户须先建「当日价/临时合同」再过磅

### 5.3 过磅台账

对齐现有纸质单与《鐵料當日磅單》字段，至少包括：

- 单号 BX（与纸质一致，租户内唯一）
- 客户、车牌、日期、进出闸时间
- 货柜号、封条号（出口场景）
- 总重、皮重、扣减、净重
- 货类明细行（可多行）、单价（合同带出）、金额
- 方向：采购 / 销售
- 关联合同
- 备注；作废状态

**计算规则：**

- 净重 = 总重 − 皮重 − |扣减|
- 一单多货类：各行净重之和必须等于本单过磅净重
- 金额 = 净重 × 单价（按行）
- 单价仅来自合同明细，过磅页不可改

**双轨：**

- 重量来源：工作人员查看仪表/旧软件显示后手录（一期）
- 打印：旧软件出纸质单；Web 保存电子记录并用同一 BX 号对账

**保存后修改策略：**

- 正式保存后：**不允许改关键业务字段**（重量、货类、单价来源、客户、合同、方向、金额）
- 发现错误：走**作废 → 重录新单**（作废单保留原 BX 号；新单使用新的 BX 号，与纸质新单一致）
- 允许改的非关键字段：备注等（须写审计日志）

**作废：**

- 作废单占号保留（对应 VOID/取消单据）
- **未核销：** 作废磅单时，自动将对应应收/应付标记为「已作废/关闭」，不留孤儿往来
- **已核销：** 须先冲销收付款，再作废磅单与往来

### 5.4 货类

- 用户可维护（如 AA、A、AB、B、PNS、工字、圆通、围街、搓球、船料等）
- 收购/出售品类均可配置
- 过磅货类必须落在所选合同允许的明细内

### 5.5 往来与收付

| 过磅方向 | 往来 |
|----------|------|
| 采购 | 应付 |
| 销售 | 应收 |

- 收/付款可关联一笔或多笔往来核销
- 收付方式结构化（现金/支票/转账等）+ 凭证号 + 备注
- 现金结余（简化）：期初 + 本期收款 − 本期付款（± 后补杂项）
- **币种默认单一：港币 HKD**（首批不做多币种）
- **期初现金：** 租户管理员或财务在启用时录入一次；首批仅支持调整期初并记审计日志，不做复杂资金调拨

### 5.6 首页指标

**经营概览（今日 / 本月）：**

- 销售额、采购额、毛利（销售额 − 采购额，概览口径，非精细成本结转）
- 过磅车次、采购/销售净重

**资金概览：**

- 已收款、已付款、现金结余、应收余额、应付余额

## 6. 与现有资料的对应关系

| 现有产物 | 系统对应 |
|----------|----------|
| 纸质秤重報告過磅單 | 电子磅单字段 + BX 单号对齐；打印暂留旧软件 |
| 鐵料當日磅單 | 过磅台账列表与日汇总（汇总报表一期后半段加强） |
| 鐵料收支記錄（正 KG=采购，负 KG=销售） | 磅单方向 + 往来金额；系统内用明确方向字段，避免符号歧义 |
| 客户分类（出口/船/大判/分判等） | 客户主数据属性 |
| 盈亏/库存估值 | 二期（依赖分拣与库存） |

说明：Excel 中寶新/源佳曾合账；系统中各为独立租户，逻辑模板相同。

## 7. 技术架构要点

### 7.1 形态

- 云端 Web（HTTPS）+ 云数据库；文件存储首批按需（暂无附件需求可不建）
- 浏览器访问（站内过磅机与外出设备）
- 界面：繁体中文为主，关键字段带英文（对齐现有磅单）

### 7.2 逻辑分层

1. 租户与账号（注册、员工、RBAC）
2. 基础参数
3. 合同域
4. 过磅域
5. 财务域（往来、收付、结余）
6. 总览（首页）

### 7.3 扩展预留

- 称重数据源接口（一期 Manual，二期 SerialBridge）
- 打印适配（一期 ExternalLegacy，二期 WebPrint）

### 7.4 防错与质量

- 租户隔离与越权拒绝
- BX 单号租户内唯一
- 净重勾稽、合同必选、单价只读
- 乐观锁防并发覆盖
- 关键操作审计日志
- 金额/重量使用精确小数

### 7.5 技术栈

实现计划阶段再选定具体框架；本规格锁定业务边界与规则，要求支持多租户、RBAC、精确金额。

## 8. 错误处理摘要

| 场景 | 处理 |
|------|------|
| 无合同过磅 | 拒绝保存 |
| 明细净重之和 ≠ 过磅净重 | 拒绝保存 |
| BX 单号重复 | 拒绝保存 |
| 修改已保存磅单关键字段 | 拒绝；须作废重录 |
| 作废未核销磅单 | 同步作废/关闭对应往来 |
| 作废已核销单据 | 先冲销收付，再作废 |
| 履约超合同约重 | 警告（默认可配硬拦截） |
| 跨租户访问 | 拒绝 |

## 9. 测试场景（一期最小集）

1. 新租户注册 → 建员工与角色 → 配货类与客户
2. 采购合同 → 多车过磅 → 应付 → 付款核销 → 首页数字正确
3. 销售合同 → 过磅（含柜号）→ 应收 → 收款核销 → 首页数字正确
4. 一单多货类、扣减、作废、单号冲突
5. 两租户数据互不可见
6. 五类角色菜单/按钮权限符合预期

## 10. 设计决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 产品形态 | 多租户 SaaS | 未来服务多家同类公司 |
| 业务中心 | 合同中心 | 规范单价与财务，降低 Excel 式出错 |
| 一期读磅 | 手录 | 旧系统对接未知；先跑通流程 |
| 一期打印 | 旧软件继续打 | 降低上线阻力；Web 同号对账 |
| 角色 | 五类可配置 | 分权清晰，适合多用户 |
| 首页 | 经营 + 资金 | 老板与财务共同需要 |
| 分拣 | 二期 | 控制一期范围 |
| 首租户 | 寶新 | 有完整现场资料可验证 |
| 开户方式 | 自助注册创建租户 | 降低开通成本；平台超管事后停用 |
| 磅单改错 | 作废重录，不改关键字段 | 保证审计与往来状态简单可靠 |
| 未核销作废 | 同步关闭往来 | 避免孤儿应收应付 |
| 币种 | 单一 HKD | 符合香港现场；避免一期多币种复杂度 |
| 实现计划边界 | 仅「首批上线」 | 与一期后半段拆分，避免计划范围失控 |
