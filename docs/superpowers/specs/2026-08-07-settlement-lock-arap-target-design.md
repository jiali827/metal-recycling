# 结算单确认锁定与应收/应付目标、往来核销设计

| 属性 | 内容 |
| --- | --- |
| 日期 | 2026-08-07 |
| 状态 | **已确认并实现** |
| 关联页面 | `/settlement-docs`、`/receivables`、`/payables`、`/payments` |
| 关联文档 | `需求文档/结算单.md`、`需求文档/应收账.md`、`需求文档/应付账.md`、`需求文档/收付款.md` |
| 前置能力 | 结算单制单、附件备份（附件不卡锁定） |

---

## 1. 目标

将财务闭环从「按磅单自动产生应收/应付」改为：

1. 结算单财务 **确认结算** 后锁定，不可再改业务内容；
2. 已确认结算单 = **一条应收或应付目标**；
3. 收付款「往来核销」只对着该目标登记，不再选手方 / 合同 / 磅单；
4. 应收/应付页展示目标金额、已收(付)、未收/余额。

---

## 2. 已确认决策

| 决策点 | 结论 |
| --- | --- |
| 目标来源 | **A. 替换**：仅已确认结算单产生应收/应付；磅单不再自动生成往来 |
| 锁定方式 | **手动**：财务点「确认结算」；附件可先传，不强制 |
| 附件与锁定 | 附件不卡锁定；锁定后仍可上传/替换/删除附件（留档） |
| 解锁 | **有条件**：仅当该目标已收/已付 = 0（无任何核销）时可「取消确认」 |
| 核销粒度 | **一笔收付款只核一张结算单** |
| 目标呈现 | **并入结算单**：列表展示已核销/余额/核销状态；侧栏不再单独放应收应付；`/receivables` `/payables` 兼容跳转结算单 |
| 部分/超额 | 允许多次部分核销；**禁止超额**（本次 ≤ 当前余额） |

方向映射：

| 结算单 kind | 财务目标 |
| --- | --- |
| `sale`（销售单） | 应收 |
| `purchase`（采购单） | 应付 |

---

## 3. 业务链路

```
制结算单（待确认，可编辑）
  →（可选）上传签字附件
  → 财务「确认结算」→ 已确认（锁定）+ 写入应收或应付目标
  → 收付款往来核销选结算目标登记（可多次部分）
  → 余额归零 → 目标状态「已结」
```

取消确认（无核销时）：

```
已确认 + 已收/已付 = 0
  → 「取消确认」→ 待确认（可编辑）+ 从应收/应付移除（或 void）
```

## 4. 结算单状态与交互

### 4.1 状态

废弃产品语义上的「草稿 / 已打印」作为财务闭环依据。本期财务闭环使用：

| 状态值（建议） | 展示文案 | 含义 |
| --- | --- | --- |
| `pending` | 待确认 | 可编辑业务字段与磅单；可传附件 |
| `confirmed` | 已确认 | 业务字段与磅单锁定；已作为应收/应付目标 |

> 实现迁移：现有 `draft` / `printed` 一律视为 `pending`（待确认）；成单默认 `pending`。

### 4.2 列表 / 详情操作

| 状态 | 可编辑业务 | 确认结算 | 取消确认 | 附件 |
| --- | --- | --- | --- | --- |
| 待确认 | 是 | 是（有编辑权限） | — | 可传/替/删 |
| 已确认 | 否 | — | 仅当目标无核销 | 仍可传/替/删 |

- **确认结算**：二次确认；成功后状态 → 已确认，并同步生成/确保对应应收或应付目标存在。
- **取消确认**：二次确认；若已存在任意往来核销收付款，禁止并提示「已有收付款核销，无法取消确认」。
- 已确认时：编辑入口隐藏或点开只读；保存类按钮不可用。
- 打印：两态均可打印（与锁定无关）。

### 4.3 确认时写入目标的字段口径

| 目标字段 | 来源 |
| --- | --- |
| 关联结算单号 | `WeighSettlementDoc.no` |
| 对方 | `customerName` |
| 合同 | `contractNo` / `contractId` |
| 目标金额 | `totalAmount` |
| 已收(付) | 初始 `0` |
| 余额 | `totalAmount` |
| 状态 | `open` |
| 业务日期 | `docDate`（或确认当日，实现时与产品一致取 `docDate`） |

明细磅单不再作为核销必选维度；详情可只读展示结算单内磅单列表（追溯用）。

## 5. 数据模型调整（Mock / 类型）

### 5.1 `WeighSettlementDoc`

| 字段 | 说明 |
| --- | --- |
| `status` | `pending` \| `confirmed`（替换原 `draft` \| `printed` 产品语义） |
| `confirmedAt?: string` | 确认时间（可选，审计） |
| `confirmedBy?: string` | 确认人（可选，演示可写当前用户名） |

附件字段保持不变。

### 5.2 `ArApItem`（应收/应付共用结构）

由「磅单 BX 一对一」改为「结算单一对一」：

| 字段 | 说明 |
| --- | --- |
| `settlementDocId: string` | 结算单 id（主键关联） |
| `settlementDocNo: string` | 结算单号（列表展示） |
| `customerName` | 对方 |
| `contractId?` / `contractNo?` | 合同（只读展示） |
| `amount` | 目标金额 = 结算单 `totalAmount` |
| `settledAmount` / `balance` | 由收付款汇总回写 |
| `status` | `open` \| `partial` \| `settled` \| `void` |
| `date` | 业务日期 |

废弃作为核销主键的 `ticketBxNo`（可保留可选追溯字段，但 UI/核销不再依赖）。

取消确认时：对应 `ArApItem` 删除或 `void`，且不得存在引用该结算单的往来收付款。

### 5.3 `PaymentRecord`（往来核销）

| 字段 | 说明 |
| --- | --- |
| `category` | `settlement` 时走新规则 |
| `settlementDocId` / `settlementDocNo` | **必填**（往来） |
| `type` | 收款 / 付款（应与目标方向一致：应收→收款，应付→付款） |
| `amount` / `method` / `date` 等 | 不变 |
| `counterparty` | **由目标带出写入**，表单不再选手方 |
| `contractNo` / `ticketBxNo` | 往来核销不再作为用户必填；可不写或只读冗余 |

杂项收支（`misc`）逻辑不变。

### 5.4 磅单与 store 行为变更

- `addWeighTicket` / 更新正常磅单：**不再**自动 `addReceivable` / `addPayable`。
- 既有 Mock 种子数据：应收/应付改为挂已确认结算单；或清空旧磅单级往来，按新规则重建演示数据。

## 6. 应收账 / 应付账

### 6.1 菜单与页面

侧边栏不单独放「应收应付」。核销进度在结算单列表展示（已核销 / 余额 / 核销状态）；收付款仍按结算目标核销。`/receivables`、`/payables` 兼容跳转到结算单。

### 6.2 列表字段（建议）

结算单列表在合计金额后增加：

| 列 | 说明 |
| --- | --- |
| 已核销 | 来自对应应收/应付目标；待确认显示 — |
| 余额 | 同上 |
| 核销状态 | 未核销 / 部分核销 / 已结清；待确认显示 — |
| 确认状态 | 待确认 / 已确认 |

## 7. 收付款 · 往来核销 UI

### 7.1 新建 / 编辑（往来）

用户选择顺序建议：

1. 类别 = 往来核销  
2. **选择结算目标**（下拉/可搜索：已确认且余额 > 0；编辑时可含本单已核目标）  
3. 带出只读：对方、合同、结算单号、目标金额、已收(付)、余额  
4. 填写：收/付类型（可按目标方向默认并锁定）、金额、方式、业务时间、摘要  

**不再出现**：选手方、选合同、选磅单。

### 7.2 校验

| 规则 | 说明 |
| --- | --- |
| 必须选已确认结算单 | 待确认不可核销 |
| 方向一致 | 销售结算 → 仅收款；采购结算 → 仅付款 |
| 金额 | `0 < 本次 ≤ 当前余额`（编辑时余额口径 = 目标金额 − 其他收付款已核金额） |
| 一单一笔 | 一条 `PaymentRecord` 只关联一张结算单 |

### 7.3 回写

保存/删除往来收付款后，按 `settlementDocId` 汇总重算对应 `ArApItem` 的 `settledAmount`、`balance`、`status`（`open` / `partial` / `settled`）。

### 7.4 列表列调整

往来行展示：结算单号、对方、金额等；弱化或移除「关联磅单 BX」作为主列（可保留次要追溯若仍有历史数据）。

## 10. 验收要点

1. 新建结算单为待确认；可编辑；确认后不可改磅单与业务字段。  
2. 无附件也可确认；确认后仍可传附件。  
3. 确认销售单 → 应收出现一条；确认采购单 → 应付出现一条；金额 = 结算单合计。  
4. 正常保存磅单不再新增应收/应付行。  
5. 往来核销只选结算目标，不选手方/合同/磅单；带出总额/已收/余额。  
6. 部分核销多次成功；超额被拒。  
7. 有核销时取消确认失败；无核销时可取消确认，目标消失，结算单恢复可编辑。  
8. 删除往来收付款后余额回滚正确。
