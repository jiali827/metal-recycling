# 运营端（平台治理）设计规格

**日期：** 2026-08-06  
**状态：** 已确认（头脑风暴）  
**关联：** [金属回收 SaaS 设计规格](./2026-08-05-metal-recycling-saas-design.md)、[前端 UI 设计规范](./2026-08-05-frontend-ui-design-system.md)  
**首个验证租户语境：** 寶新等企业端用户；本规格描述**平台运营方**侧产品

---

## 1. 背景与目标

### 1.1 问题

现有一期设计以**企业端（租户内业务）**为主。平台侧仅原则性提到「平台超管可停用/启用租户」，且原开户方式为「企业自助注册」。实际产品方向已调整为：

- 企业端**不做**自助注册
- 需要独立、可长期演进的**运营端**，而不是企业端里的临时管理页

### 1.2 目标

建设独立的**运营端 Web 应用**，作为平台治理底座：

- V1 只交付**租户治理**（代建、启停、重置主管理员密码、审计）
- 账号与权限模型、租户状态机、审计可扩展，便于后续加计费、公告、工单等，**不必推倒重来**
- 默认**不查看**各租户业务明细（合同、过磅、往来等）

### 1.3 成功标准（V1）

1. 平台超管可代建租户并指定主管理员；企业端可用该账号登录；企业端无自助注册入口  
2. 停用后该租户全员无法登录，已有会话立即失效；数据保留；启用后恢复  
3. 普通运营可查看租户元数据、重置主管理员密码；不能建租户、不能启停  
4. 运营端界面与 API 均拿不到企业业务数据  
5. 建租户 / 启停 / 重置密码均有可追溯审计（不含密码明文）  
6. 运营端与企业端为**独立应用、独立登录**；视觉风格对齐企业端，**不共享业务页面**

## 2. 范围

### 2.1 V1 包含

| 模块 | 要点 |
|------|------|
| 平台账号与权限 | 运营登录；预置「平台超管 / 普通运营」；按权限点鉴权 |
| 租户治理 | 代建、列表/筛选、详情、启用/停用、重置主管理员密码 |
| 审计日志 | 关键操作写入并可筛选查询（只读） |

### 2.2 V1 明确不做

- 套餐 / 计费 / 欠费自动停用  
- 工单、代登录、查看或导出企业业务数据  
- 跨租户经营看板（活跃度等聚合指标）  
- 平台公告推送  
- 运营端完整「运营员工 CRUD」配置 UI（见 §4.3：种子/部署配置即可）  
- 租户硬删除  

### 2.3 扩展预留（不做 UI，模型留位）

- 权限点按 `module.action` 扩展（如未来 `billing.*`、`announce.*`）  
- 租户状态机可增加态（如 `pending`），不影响 V1 的 `active` ⇄ `suspended`  
- 审计 `action` 枚举可扩展  
- 侧栏预留空分组位，V1 不展示未启用模块  

### 2.4 对本仓库既有规格的修订

| 原约定（SaaS 设计规格） | 本规格生效后 |
|-------------------------|--------------|
| 开户：自助注册即创建租户 | **运营代建**；企业端注册下线 |
| 平台超管：启停等；无独立应用描述 | **独立运营端** + 分级角色 + 代建 + 重置主管理员密码 |
| 平台默认不看业务明细 | **保持**；V1 仍禁止业务数据访问 |

实现企业端时，须同步去掉/禁用注册入口，登录仅接受「所属租户为 `active`」的企业账号。

## 3. 用户与产品边界

### 3.1 两端对比

| | 企业端 | 运营端 |
|--|--------|--------|
| 用户 | 回收公司员工 | 平台运营人员 |
| 开户 | 无自助注册；仅已开通且未停用的租户可登录 | 代建租户 + 指定主管理员 |
| 数据范围 | 本租户业务数据 | 租户元数据 + 平台账号；**无**业务明细 |
| 停用影响 | 无法登录、会话失效 | 由运营发起启停 |

### 3.2 登录隔离

- 运营账号**不能**登录企业端  
- 企业账号**不能**登录运营端  
- 租户 `suspended` 时，该租户下所有企业账号一律拒绝登录，并吊销已有会话 / 刷新令牌

## 4. 角色与权限

### 4.1 预置角色

| 角色 | 能力 |
|------|------|
| **平台超管** | 建租户、启停、查看详情、重置主管理员密码、查看审计；管理运营账号（若后续开放 CRUD） |
| **普通运营** | 租户列表/详情（元数据只读）、重置主管理员密码、查看审计；**不能**建租户、启停 |

### 4.2 权限点（V1）

| 权限点 | 超管 | 普通运营 |
|--------|:----:|:--------:|
| `tenant.read` | ✓ | ✓ |
| `tenant.create` | ✓ | |
| `tenant.suspend` | ✓ | |
| `tenant.resume` | ✓ | |
| `tenant.reset_admin_password` | ✓ | ✓ |
| `audit.read` | ✓ | ✓ |
| `ops_user.manage` | ✓（预留） | |

前端按权限隐藏操作；API 必须二次鉴权，越权返回 403。

### 4.3 运营账号供给（V1）

不做完整运营员工管理 UI。通过种子数据 / 部署配置提供至少：

- 1 个平台超管  
- 可选 1 个普通运营（便于验收分级）  

`ops_user.manage` 权限点保留，供后续模块启用。

## 5. 关键业务流程

### 5.1 代建租户（仅超管）

**输入：**

- 公司中文名、英文名（可空策略由实现计划定，至少中文名必填）  
- 主管理员：姓名、邮箱  
- 可选：运营内部备注（企业端不可见）  

**初始密码策略（二选一，实现计划锁定一种）：**

- 系统生成一次性临时密码，仅在创建成功时展示给超管（须提示立即转交）；或  
- 向主管理员邮箱发送重置链接  

**结果：**

- 租户状态 = `active`  
- 创建企业侧主管理员账号（租户内「系统管理员」）  
- 写审计 `tenant.create`  

**邮箱约束：** 企业用户邮箱建议**全局唯一**，避免一人跨租户身份混乱；重复则拒绝创建。

### 5.2 停用（仅超管）

1. 二次确认  
2. 状态 → `suspended`，记录 `suspendedAt`  
3. 吊销该 `tenant_id` 下全部企业会话 / 刷新令牌  
4. 写审计 `tenant.suspend`  

数据不删除，可再启用。对已停用租户再次停用：幂等成功或提示「已是停用状态」。

### 5.3 启用（仅超管）

1. 状态 → `active`  
2. 写审计 `tenant.resume`  
3. 企业账号可再次登录（密码未改则仍用原密码）  

### 5.4 重置主管理员密码（超管 + 普通运营）

- 仅针对该租户**主管理员**一人；运营端**不**列出其他员工  
- **允许**在租户已停用时重置（便于启用前把凭证交给客户）；审计中记录操作时租户状态  
- 交付方式与代建一致（临时密码展示或重置链接）；审计**不写**明文或密码哈希  
- 写审计 `tenant.reset_admin_password`  

### 5.5 状态机

```text
（代建）→ active ⇄ suspended
```

V1 不引入 `pending` / `deleted`。不做硬删除。

## 6. 信息架构

### 6.1 路由（V1）

```text
/login                    运营登录（独立入口）
/tenants                  租户列表（关键词、状态筛选）
/tenants/new              代建租户（仅超管；无权限则不可达）
/tenants/:id              租户详情（元数据 + 启停 / 重置密码）
/audit                    审计日志（筛选：租户、操作类型、时间、操作人）
```

### 6.2 列表 / 详情可见字段（元数据 only）

- 租户 ID、公司中/英文名、状态（`active` / `suspended`）  
- 创建时间、最近启停时间  
- 主管理员：姓名、邮箱（无密码）  
- 运营内部备注（可选）  

### 6.3 视觉与工程边界

- **视觉：** 对齐企业端 Soft UI / 主题与组件观感（参见 UI 设计规范）  
- **工程：** 独立前端应用（如 monorepo 下 `apps/ops` 或仓库根目录 `ops/`）；**不共享企业业务页面**  
- 允许共享：设计 token、基础 UI 原子组件、类型/API 契约；禁止共享：企业业务路由、Mock 业务页、租户业务布局壳作为运营壳直接复用  

部署上优先**分离登录域 / Cookie**，降低串会话风险。

## 7. 逻辑数据模型

| 实体 | 职责 |
|------|------|
| `PlatformUser` | 运营人员账号（与企业 `Employee` 分表/分域） |
| `PlatformRole` + 权限绑定 | 超管 / 普通运营 |
| `Tenant` | `id`, `name`, `nameEn`, `status`, `createdAt`, `suspendedAt?`, `opsNote?` |
| `TenantPrimaryAdmin` | 指向该租户主管理员（企业用户）；重置密码只针对此人 |
| `AuditLog` | `actorId`, `action`, `tenantId?`, `metadata`(脱敏), `result`, `createdAt` |

运营侧 API **禁止**查询合同、过磅、往来等业务表。企业业务表继续带 `tenant_id`，企业 API 强制租户校验且校验租户为 `active`。

## 8. 异常与安全

| 场景 | 处理 |
|------|------|
| 普通运营访问建租户 / 启停 | 前端隐藏 + API 403 |
| 主管理员邮箱重复 | 拒绝创建并提示 |
| 停用已停用 / 启用已启用 | 幂等或明确「已是该状态」 |
| 运营账号调用企业业务 API | 拒绝（无业务 scope） |
| 企业账号调用运营 API | 拒绝 |
| 停用瞬间已登录的企业用户 | 后续请求 401；刷新令牌失效 |

---

## 9. 审计

**必记 action：**

- `tenant.create`  
- `tenant.suspend`  
- `tenant.resume`  
- `tenant.reset_admin_password`  

每条含：操作人、时间、租户 ID（如有）、成功/失败、必要脱敏元数据。禁止记录密码明文或可逆凭证。

---

## 10. 测试场景（V1 最小集）

1. 超管代建租户 → 主管理员可登录企业端；企业端无注册入口  
2. 超管停用 → 该租户账号无法登录；已登录会话失效 → 启用后可再登录  
3. 普通运营：可重置主管理员密码；建租户 / 启停 API 与 UI 均不可用  
4. 运营端任意路径无法读取业务明细数据  
5. 上述关键操作均可在审计中按租户/操作人/时间查到  
6. 运营账号无法登录企业端；企业账号无法登录运营端  
7. 停用状态下重置主管理员密码成功，且审计记录当时状态

## 11. 设计决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 产品形态 | 独立运营端应用 | 与企业端隔离；利于长期扩展 |
| V1 范围 | 仅租户治理 + 审计 + 分级权限底座 | 先做稳；计费/工单等后置 |
| 开户 | 运营代建，企业自助注册取消 | 符合当前产品决策；可控开户 |
| 介入深度 | 可重置主管理员密码；不看业务、不代登录 | 兼顾排障与数据隔离 |
| 停用语义 | 全员禁登 + 会话失效 + 数据保留 | 安全清晰、可恢复 |
| 运营账号 UI | V1 种子/配置，CRUD 后置 | 降低首版范围，权限点仍预留 |
| 视觉 | 对齐企业端风格，不共享业务页面 | 品牌一致且边界清晰 |
| 架构策略 | 平台治理底座 + 模块可扩展 | 避免精简壳推倒重来，也避免一上来做重中台 |
