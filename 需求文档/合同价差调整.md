## 1. 问题定义

### 1.1 与零头减免的本质区别

| | 零头减免（抹零） | 合同价差调整 |
| --- | --- | --- |
| 账面价是否正确 | 正确（单价没错） | **不正确**（单价变了） |
| 差额性质 | 让免零头，无商业实质 | 真实购销价差，商业实质变更 |
| 修正位置 | 收付款核销层（披露） | 合同层或结算单层（**修正账面金额**） |
| 经营口径 | 不进销售额/毛利 | **必须进**销售额/毛利 |
| 金额量级 | 几角，无上限 | 无固定量级，可为正可负 |
| 后续影响 | 仅本笔收款 | 未来磅单价、履约金额 |

**禁止把价差记成减免**（否则毛利失真、账实两层错位）。

### 1.2 价格正源原则（v3.0 核心）

| 原则 | 说明 |
| --- | --- |
| 合同 = 唯一价格正源 | 一次性合同模型下，每次合作的成交价依据就是该合同；合同价与磅单价必须一致 |
| 过磅单价只读（R02 恢复原版） | 挂合同磅单的单价**锁死**，来源于合同明细；不允许在过磅环节改价（v2.0 的过磅改价方案已撤回，见 §9） |
| 价格变了 = 合同变了 | 过磅时谈定新价 → 先做**合同改价**（留变更历史），再过磅；之后的磅单按新价带出 |
| 已入账磅单的价差 | 磅单已按旧价入账、之后才谈定新价 → 走**结算单价差调整行**，留痕 |

### 1.3 典型场景

- 销售合同约定 AA 货 $2.30/kg，**合作期间价格谈变**为 $2.25/kg → 做一次合同改价，之后所有磅单按 2.25 带出，合同与磅单一致
- 某几车已按 2.30 入账，结算时双方议定这几车按 2.25 结 → 结算单录价差调整行（差额 -0.05 × 净重）
- 采购方向对称适用

## 2. 核心方案：按三个时点分流（v3.0 恢复）

```
时点 1：还没过磅，价格已谈变（★ 主路径）
  → 合同改价（合同变更，变更留痕：原价→新价、变更人、时间、原因）
  → 之后磅单按新价自动带出，合同与过磅记录始终一致

时点 2：磅单已按合同价入账、结算单未确认，之后才谈定价差
  → 结算单编辑弹窗录入「价差调整行」，结算总额 = 磅单合计 + 价差合计

时点 3：结算单已确认（甚至已核销）才发现价差
  → 无核销：取消确认 → 调整价差 → 重新确认（结算单重打签字）
  → 有核销：财务先冲销 → 取消确认 → 调整 → 重新确认 → 重新核销
```

### 2.1 不改磅单（关键决策，v3.0 维持并强化）

| 依据 | 说明 |
| --- | --- |
| 一次性合同模型 | 价格正源是合同；磅单改价会让合同与过磅记录脱钩，对账失据（v2.0 撤回原因） |
| W08 已保存磅单不可改关键字段 | 重量、单价、金额均锁死；录错走作废重录 |
| 纸质单对齐（R05） | 磅单按合同价入账；若双方按新价成交，差异在结算层以价差行显性修正，来龙去脉可查 |
| 结算单是结算快照 | 双方按结算单签字收付；事后议定的价差天然落在结算环节 |
| 一张结算单只绑一个合同 | 价差归属清晰，无跨合同分摊问题 |

## 3. 功能需求

### 3.1 合同改价（时点 1，★ 主路径）

| 规则 | 说明 |
| --- | --- |
| 入口 | 合同详情 → 修改货类单价（生效/履约中合同允许） |
| **过磅锁定** | **合同已产生有效（未作废）过磅记录后，禁止变更**（改价或其他信息均不可）；「变更合同」按钮隐藏并在底部显示锁定原因。价格正源已落磅单，再改合同会导致合同与过磅记录对不上（PD12） |
| 变更历史 | 每次改价记录：变更前单价 → 变更后单价、变更人、变更时间、原因（投产审计） |
| 磅单带价 | 改价保存后，新过磅的磅单按**新价**带出；历史磅单金额不变（当时按旧价成交） |
| 履约口径 | 履约进度仍按重量，不受改价影响 |
| 与价差调整衔接 | 旧价期间已入账的磅单需按新价结算的，走时点 2/3 的价差调整 |

**Mock 实现（v3.1，已落地）**：合同详情弹窗新增「变更合同」入口，不仅限改价——客户、联系人、项目、有效期、备注、付款条件、约量、明细单价等字段均可变更；保存时按字段级 diff 生成变更记录（字段名、旧值→新值、原因必填、操作人、时间），追加到合同的 `revisions[]` 并在详情「变更记录」区展示。变更期间状态字段锁定（防止误改生命周期）。改动文件：`entities/contract/revision.ts`（diff 引擎，含 6 条 vitest 用例）、`features/contracts/components/ContractModals.tsx`（采购/销售详情弹窗）、`entities/types.ts`（`ContractRevision`/`ContractChange`）。

### 3.2 结算单价差调整行（时点 2）

新建/编辑结算单（待确认）时，磅单明细汇总区下方新增「价差调整」区：

| 字段 | 控件 | 必填 | 说明 |
| --- | --- | --- | --- |
| 货物类型 | 下拉 | 是 | 从所选磅单涉及的货类中选择 |
| 原单价 | 只读展示 | — | 合同明细单价快照 |
| 实际单价 | 数字输入（HK$/KG） | 是 | 双方实际谈定的结算单价 |
| 涉及净重 | 只读展示 | — | 本结算单内该货类磅单净重合计 |
| 价差金额 | 只读自动计算 | — | `(实际单价 − 原单价) × 涉及净重`，可为负 |
| 原因 | 文本输入 | 是 | 如「双方重新议价」「市场价回调」 |

**汇总规则：**

| 规则 | 说明 |
| --- | --- |
| 结算总额 | `Σ磅单金额 + Σ价差金额`；仅展示磅单小计、价差小计、总额三行 |
| 同货类唯一 | 一个货类只允许一条价差调整行（重复录入提示合并） |
| 实际单价 ≠ 0 | 不限制正负方向；与原单价相同时不录（差额为 0 无意义） |
| 打印页 | 明细表后展示「价差调整」段（货类、原价、实际价、差额、原因）与调整后总额 |

### 3.3 确认与往来（衔接既有链路）

| 环节 | 行为 |
| --- | --- |
| 确认结算 | 应收/应付目标金额 = **调整后总额**（含价差）；锁定结算单与价差行 |
| 收付款核销 | 上限为调整后余额；零头减免（`零头减免.md`）照常叠加——**价差和抹零两层互不干扰** |
| 取消确认 | 价差行随结算单解锁，可修改后重新确认 |
| 删除结算单 | 仅待确认可删；价差行随单删除 |
| 冲销/回退 | 按既有核销冲销流程；价差随结算单取消确认回退 |

### 3.4 经营口径修订（首页）

| 指标 | 口径 |
| --- | --- |
| 销售额 / 采购额 | `Σ normal 磅单金额 + Σ 已确认结算单价差金额`（销售单价差进销售额，采购单进采购额） |
| 毛利概览 | 调整后销售额 − 调整后采购额（真实毛利） |
| 已收/已付/现金结余 | 不变（只按实收实付，价差与减免均不入现金） |

> 无价差调整时，口径退化为现有 D02/D03，完全兼容。价差在**结算单确认时点**归属到经营期间。

## 4. 业务规则（编号 PD）

| 编号 | 规则 |
| --- | --- |
| PD01 | 价差是商业实质变更，禁止通过减免/抹零渠道处理；二者机制严格分离 |
| PD02 | 合同是价格正源（一次性合同模型）：挂合同磅单单价只读、来源于合同明细（R02）；已保存磅单金额与单价不因价差修改（W08），价差在合同层或结算单层修正 |
| PD03 | 价差调整行 = 货类 + 原单价快照 + 实际单价 + 涉及净重 + 自动差额（可负）+ 必填原因；同货类唯一 |
| PD04 | 结算总额 = Σ磅单金额 + Σ价差差额；确认后往来目标金额 = 调整后总额 |
| PD05 | 经营口径：销售额/采购额 = normal 磅单金额 + 已确认结算单价差（价差在确认时点归属期间）；无价差时退化为 D02/D03 |
| PD06 | 已确认结算单调价差须先取消确认（无核销）或先冲销（有核销），不得绕过锁定 |
| PD07 | 未过磅时价格谈变 → 合同改价（变更留痕：前后单价、变更人、时间、原因）；改价后新磅单按新价带出，历史磅单金额不变 |
| PD08 | 价差调整与改价均留痕审计（投产口径） |
| PD09 | 价差与零头减免可叠加：往来金额（含价差）→ 核销时仍可抹零；减免规则 WV01–WV09 不变 |
| PD10 | **禁止在过磅环节修改挂合同磅单的单价**（v3.0 撤回 v2.0 过磅改价方案）；价格变化一律先走合同改价 |
| PD11 | 合同与过磅记录一致性：同一合同周期内，所有磅单单价必须与合同当前（或当时）明细价一致；不一致只能通过时点 2/3 显性修正并留原因 |

## 5. 数据模型变更（结算单）

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| priceAdjustments | PriceAdjustment[] | 价差调整行数组；空数组表示无调整 |
| priceAdjustments[].materialName | string | 货物类型名称 |
| priceAdjustments[].origPrice | number | 原单价快照（HKD/KG） |
| priceAdjustments[].actualPrice | number | 实际结算单价 |
| priceAdjustments[].netKg | number | 涉及净重（该货类本结算单合计） |
| priceAdjustments[].amount | number | 价差金额（自动计算，可负） |
| priceAdjustments[].reason | string | 调整原因 |
| adjustedTotal | number | 调整后总额（保存时计算写入；= ticketsTotal + Σamount） |

> 磅单数据模型**无变更**（v2.0 提议的 contractUnitPrice/priceReason/priceDeviated 已随过磅改价方案一并撤回）。

## 6. 边界场景

| 场景 | 处理 |
| --- | --- |
| 过磅时才发现价格谈变了 | 先做合同改价（时点 1），再新建磅单按新价带出；**不在过磅页改价** |
| 磅单已按旧价入账后才谈定价差 | 结算单录价差调整行（时点 2） |
| 价差为负（新价低于原价） | 允许；销售额/采购额相应调低，可为负差额 |
| 已确认 + 已部分核销后谈定价差 | 财务冲销已有核销 → 取消确认 → 调整 → 重新确认 → 重新核销 |
| 多个货类同时变价 | 合同改价逐货类修改；结算层每货类一条调整行，互不影响 |
| 结算单未涉及价差 | 不录调整行，行为与现状完全一致 |
| 价差与抹零同时发生 | 结算总额按调整后口径 → 往来 → 收款时再抹零头，两层各自留痕 |
| 价格长期回调（连续多车新价） | 做一次合同改价即可，后续磅单自动带新价；无需每车处理 |
| 合作结束、下次再谈新价 | 新建合同（一次性合同模型），旧合同与旧磅单不受影响 |
| 合同已完成后再谈价差 | 该合同历史磅单已结算的按已结算口径；未结算磅单仍可开新结算单调价差 |
| 过磅员发现单价带出错了 | 未保存：直接重选货类/重带；已保存：作废重录（R07/W08），不是"改价" |

## 7. 验收标准

| 验收点 | 验收标准 |
| --- | --- |
| 单价锁定 | 挂合同磅单单价只读、按合同带出；无合同磅单手工录入（现状保留） |
| 合同改价 | 改价后新磅单按新价带出；历史磅单金额不变；变更历史可查（原价→新价、人、时间、原因） |
| 合同-磅单一致 | 同一合同周期内所有磅单单价与合同明细价一致；trace 面板无矛盾数据 |
| 价差录入 | 编辑结算单可添加/删除价差行；差额自动计算正确；原因必填 |
| 汇总 | 结算总额 = 磅单小计 + 价差小计；列表与打印页一致 |
| 确认 | 确认后往来目标金额 = 调整后总额；核销上限随之 |
| 取消确认 | 可取消并修改价差后重新确认；有核销时被拦（沿用既有规则） |
| 经营口径 | 首页销售额/采购额含已确认价差；毛利为调整后真实值 |
| 机制隔离 | 价差不出现在减免统计；减免不出现在价差汇总；两者可叠加且互不影响 |
| 打印 | 打印页含价差调整段与调整后总额 |

## 8. 范围边界

- 合同改价与变更历史（Mock 演示级）
