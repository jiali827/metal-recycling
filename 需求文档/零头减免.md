## 1. 问题定义

### 1.1 场景

散户（`retail`）销售过磅后现金付款，计算金额 = 净重 × 单价（如 HK$ 1,000.40），客户实际只付整数（如 HK$ 1,000），差额 HK$ 0.40 公司惯例不收（抹零）。

### 1.2 若不专门设计会出现的问题

| 问题 | 后果 |
| --- | --- |
| 应收按计算金额记，实收少几角 | 核销后往来永远差几角，卡在「部分核销」，残差越积越多，应收余额虚高 |
| 直接改磅单金额 / 单价 | 违反「单价来自合同、过磅页只读」「已保存磅单不可改关键字段」；与纸质 BX 单对不上；销售额口径失真 |
| 差额记成杂项收入 | 方向反了（少收不是收入）；污染杂项类别统计 |
| 不记录、口头说明 | 后续对账时无人知道为什么差几角 |

### 1.3 设计目标

1. **账实分离**：账面（磅单/往来）按计算金额走；实收与账面的差额作为「减免」单独记录
2. **可追溯**：任何时候都能看到「这单为什么少收了几角」——谁减免、减了多少、什么原因
3. **不污染**：销售额/毛利口径、合同履约、现金结余、应收余额都不因此出错或产生残差

---

## 2. 核心方案

### 2.1 三笔账分清

```
账面金额（磅单/结算单/往来）= 净重 × 单价        ← 永远不动
实收金额（收付款 amount）    = 客户真实现金      ← 进现金结余
减免金额（waiverAmount）     = 账面 − 实收的差额  ← 单独记录，不进现金
核销有效额 = 实收金额 + 减免金额                  ← 用于往来结清判定
```

### 2.2 各模块数据流向（确认不互相污染）

| 模块 | 是否受影响 | 说明 |
| --- | --- | --- |
| 磅单台账 | ❌ 不变 | 金额仍按净重×单价，与纸质单对齐（R05） |
| 合同/履约 | ❌ 不变 | 履约按重量累计，与金额无关 |
| 销售额/采购额/毛利（首页） | ❌ 不变 | 仍按磅单金额（D02/D03 口径）；账面销售与实收的差 = 减免合计，逻辑自洽 |
| 应收/应付余额 | ✅ 正向改善 | 结清判定含减免后核销即归零（settled），不再残差挂账 |
| 已收/已付/现金结余（首页） | ❌ 不变 | 只按收付款 `amount`（实收实付）计算（D01/D04'），减免不入现金 |
| 结算单 | ❌ 不变 | 金额为账面口径；结清展示由往来层处理 |
| 收付款 | ✅ 新增字段 | 新增减免金额 + 减免原因（见 §3） |

## 3. 功能需求

### 3.1 登记核销弹窗（收付款 · 往来核销）

字段顺序：类型 → 关联结算单 → 方式 → 金额 → **减免金额（新增）** → 收付时间。

| 字段 | 控件类型 | 必填 | 默认值 / 限制 | 说明 |
| --- | --- | --- | --- | --- |
| 减免金额 Waiver ($) | 数字输入 + HK$ 单位 | 否 | 默认 `0`；步进 `0.01` | 本次核销中不实际收付、直接让免的金额 |
| 减免原因 | 文本输入 | 否 | 默认「抹零」 | 减免 > 0 时建议填写；随记录保存 |

**联动规则：**

| 规则 | 说明 |
| --- | --- |
| 校验 | `实收金额 + 减免金额 ≤ 所选目标余额`；实收金额仍须 `≥ 0` |
| 实时合计提示 | 表单下方展示：「实收 HK$X ＋ 减免 HK$Y ＝ 核销 HK$Z（目标余额 HK$B）」 |
| 默认值联动 | 选择结算单后金额默认带出余额；若用户将金额改为「整数金额」，减免金额可自动预填差额（`余额 − 金额`），可清零 |
| 结清判定 | `实收 + 减免 ≥ 目标余额` 时，往来结清（settled）；否则按部分核销 |
| 摘要 | 减免 = 0 时不变：`核销 {结算单号}`；减免 > 0 且结清：`核销 {结算单号}（减免 HK$0.40）`；部分核销同理前缀「部分核销」 |

### 3.2 收付款列表与详情

| 位置 | 变更 |
| --- | --- |
| 列表新增「减免」列 | 展示 `waiverAmount`；为 0 时显示「—」；金额列保持只显示实收实付 |
| 详情弹窗 | 展示减免金额、减免原因；展示结清构成「实收 X ＋ 减免 Y ＝ 账面 Z」 |
| 摘要区 StatCard | 由 4 格扩展为 5 格：新增「减免金额」（区间内 waiverAmount 合计，收付双向均含） |
| 关键词筛选 | 拼接串纳入减免原因文本 |

### 3.3 往来 / 应收应付详情

结清记录需可见减免构成：`已核销 HK$1,000.40（实收 1,000.00 ＋ 减免 0.40）`。往来列表的已核销列口径 = 实收 + 减免合计。

### 3.4 首页 / 报表口径

| 指标 | 口径 | 是否含减免 |
| --- | --- | --- |
| 销售额 / 采购额 / 毛利 | 磅单金额 | 否（账面口径） |
| 已收款 / 已付款 / 现金结余 | 收付款 amount | 否（实收实付） |
| 减免金额（新指标） | waiverAmount 合计 | — |

> 对账恒等式：**销售额 − 已收款 − 减免合计 ≈ 应收余额变动**；减免单独成列后该恒等式可被逐笔核对。

## 4. 业务规则（新增，编号 WV）

| 编号 | 规则 |
| --- | --- |
| WV01 | 磅单、结算单、往来金额一律按计算金额入账，禁止因抹零调整账面金额 |
| WV02 | 减免只发生在收付款核销环节，记录在收付款单上（`waiverAmount` + `waiverReason`） |
| WV03 | 有效核销额 = 实收实付金额 + 减免金额；不得超过往来余额；不得为负 |
| WV04 | 往来结清判定改为：Σ(核销实收 + 核销减免) ≥ 往来金额 → settled |
| WV05 | 现金结余、已收已付、销售额等一切资金与经营指标均**不含**减免；减免仅作为独立披露指标 |
| WV06 | 减免金额**不设上限**（v1.2 取消原 HK$1.00 上限，不限制用户）；金额录入后照常入账，凭 WV07 留痕追溯 |
| WV07 | 减免记录须留痕：操作人、时间、原因（审计日志，投产口径） |
| WV08 | 删除/编辑/冲销核销记录时，减免随核销一并回退，往来余额按「实收+减免」口径回滚 |
| WV09 | 采购方向（应付）同样适用：供应商少收几角时按减免处理，规则对称 |

---

## 5. 数据模型变更（收付款记录）

| 字段名 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| waiverAmount | number | 0 | 减免金额（HKD，2 位小数） |
| waiverReason | string? | 「抹零」 | 减免原因；waiverAmount=0 时不存或存 `-` |

> 当前原型一笔收付只核销一笔结算目标，减免放单据级字段即可；二期支持一笔核销多笔往来时，减免应下移到核销分配行（allocation）级别，规则 WV03/WV04 按行校验。

## 6. 边界场景

| 场景 | 处理 |
| --- | --- |
| 只减免不收钱（全额抹零，如 HK$0.40 全免） | 实收金额 = 0 且减免 = 余额：允许；往来直接结清 |
| 部分核销 + 减免 | 允许；实收 + 减免 < 余额时仍为 partial |
| 减免金额较大 | 不设上限（WV06 v1.2），正常录入保存；原因 + 操作人留痕可追溯 |
| 作废已结清（含减免）的往来 | 按既有冲销流程：先冲销核销（含减免回退），再作废 |
| 多币种 | 一期固定 HKD，不涉及 |

## 7. 验收标准

| 验收点 | 验收标准 |
| --- | --- |
| 核销弹窗 | 可录入减免金额与原因；实时展示「实收＋减免＝核销」合计；超额被拒 |
| 结清判定 | 实收 1,000.00 + 减免 0.40 = 应收 1,000.40 → 往来 settled，余额 0，无残差 |
| 列表展示 | 收付款列表「减免」列正确；减免 > 0 的记录摘要含「（减免 HK$x.xx）」 |
| 详情展示 | 详情可见减免金额、原因与结清构成 |
| 摘要区 | 减免金额 StatCard 合计正确，随筛选联动 |
| 资金口径 | 现金结余/已收已付只按实收实付变化，减免不产生现金变动 |
| 经营口径 | 销售额按磅单金额不变；销售额 − 实收 − 减免 与应收余额变动勾稽一致 |
| 回退 | 删除含减免的核销记录后，往来余额按「实收+减免」全额回滚 |

---

## 8. 范围边界

### 8.1 本期包含

- 登记核销弹窗的减免金额/原因录入与校验
- 收付款列表减免列、详情减免构成、摘要区减免 StatCard
- 往来结清判定口径调整（实收+减免）
- 采购/销售双向适用

### 8.2 本期不包含

- 减免审批流（如后续需要大额减免审批，投产再议）
- 分配行级减免（随一笔核销多笔往来二期一并做）
- 减免报表/导出
